## スライス一覧

### [x] S0 歩くスケルトン
- 内容: git 初期化、`site/` と `worker/` の土台。Worker は受け取った文字をそのまま返すだけ（AIなし）。画面から送ると返ってくる
- 受け入れ基準: `npm test` と型チェックが通る／ローカルで画面から送信すると、Worker からの返事が表示される
- 確認方法: `wrangler dev` と静的サーバーを起動し、ブラウザで送信

### [ ] S1 Claude が答える（US-1）
- 内容: Worker から Claude API を呼ぶ。キーは `.dev.vars`（Git除外）。まだストリーミングなし
- 受け入れ基準: 「こんにちは」と送ると Claude の回答が表示される／キーがサイト側のどこにもない
- 確認方法: ローカルで送信／`site/` をキーの文字列で検索して0件

### [ ] S2 プロフィールに基づいて答える（US-1, US-2）
- 内容: `profile.md`（ひな形）と `prompt.md` を Worker に同梱し、指示文を組み立てる
- 受け入れ基準: 書いてあることは正しく答える／書いてないことは「分からない」と答える／無関係な依頼（「Pythonのコード書いて」）は断る
- 確認方法: 質問リスト10個で確認。指示文の組み立てを単体テスト

### [ ] S3 会話の継続と検証（US-3）
- 内容: 会話の配列を送る。Worker 側で形・並び・500字・10件を検証
- 受け入れ基準: 追加質問が前の話題を踏まえる／不正な要求は400で弾かれ、APIは呼ばれない
- 確認方法: 画面で2往復／`validate.ts` の単体テスト

### [ ] S4 ストリーミング表示
- 内容: SSE で回答を少しずつ返し、画面に順に表示
- 受け入れ基準: 回答が2秒以内に出始める／送信中は送信ボタンが押せない／通信失敗時にエラー表示
- 確認方法: ブラウザで確認、ネットワークを切ってエラー表示を確認

### [ ] S5 乱用対策（US-5）
- 内容: CORS の許可元制限、IPごとの回数制限、1日上限（KV）、回答長上限
- 受け入れ基準: 1分に11回送ると制限メッセージ／上限到達後はAPIを呼ばない／許可していないOriginからは拒否
- 確認方法: 連続送信、curl で別Originを指定、`limits.ts` の単体テスト

### [ ] S6 見た目と質問例（US-4）
- 内容: 見出し（名前・一言・リンク）、吹き出し、質問例ボタン、スマホ対応、a11y
- 受け入れ基準: 幅360pxで崩れない／質問例を押すと送信される／Enter送信・Shift+Enter改行
- 確認方法: ブラウザのスマホ表示で確認

### [ ] S7 公開
- 内容: Worker を Cloudflare にデプロイ（Secret設定）、GitHub Actions で `site/` を Pages に公開、README に更新手順（profile.md を直して再デプロイ）
- 受け入れ基準: PRD の成功基準をすべて満たす
- 確認方法: 公開URLをスマホで開いて確認
